## 一、核心贡献

BLIP 提出两个创新：(1) **MED 模型**——统一的视觉-语言预训练架构，同时支持理解与生成；(2) **CapFilt 数据自举机制**——从噪声网络数据中提炼高质量图文对。

---

## 二、MED：Multimodal Mixture of Encoder-Decoder

### 1. 设计动机
- 已有 VLP 模型存在功能分离问题：编码器模型（如 CLIP）擅长理解不擅长生成；编码器-解码器模型（如 Oscar）擅长生成不擅长理解。
- BLIP 的 MED 用一个统一架构同时胜任两类任务。

### 2. 三种运行模式 (P.3, "In order to pre-train a unified model with both understanding and generation capabilities")

| 模式 | 架构 | 用途 |
|------|------|------|
| 单模态编码器 | ViT + 双向 SA（文本） | 图像和文本独立编码，用于对比学习 (ITC) |
| 图像引导的文本编码器 | 双向 SA + CA（交叉注意力） | 跨模态理解，用于图文匹配 (ITM) |
| 图像引导的文本解码器 | 因果 SA（单向）+ CA | 自回归生成，用于语言建模 (LM) |

### 3. 参数共享策略
- **共享部分**: 交叉注意力层 (CA) 和前馈网络 (FFN)
- **不共享部分**: 自注意力层 (SA)——编码需双向注意力，解码需因果注意力，共享会导致性能下降 (P.6, "If the SA layers are shared, the model's performance would degrade")
- **效果**: 参数量比完全不共享减少约 30%（从 361M 降至 252M）

### 4. 联合预训练目标
- **ITC（Image-Text Contrastive Loss）**: 对比学习，拉近匹配对、推远不匹配对
- **ITM（Image-Text Matching Loss）**: 二分类，判断图文是否匹配
- **LM（Language Modeling Loss）**: 自回归预测文本 token

## 三、CapFilt：Captioning and Filtering

### 1. 设计动机
网络收集的图文对（CC、SBU 等）噪声大，直接使用会降低模型性能。（P.4, "Both the captioner and the filter are initialized from the same pre-trained MED model"）

### 2. 两个核心模块
| 模块 | 基于 MED 的哪种模式 | 在 COCO 上微调的目标 | 功能 |
|------|---------------------|---------------------|------|
| Captioner（描述器） | 解码器模式 | LM 损失 | 为网络图片生成合成描述 |
| Filter（过滤器） | 编码器模式 | ITC + ITM 损失 | 判断图文是否匹配，过滤噪声 |

### 3. 关键发现
- Captioner 和 Filter 不能共享参数：共享会产生"确认偏差"（confirmation bias），Captioner 生成的噪声描述容易被 Filter 放行。（P.6, "Due to parameter sharing, noisy captions produced by the captioner are less likely to be filtered out"）
- 噪声比例从 25% 降至 8%，说明共享会弱化过滤效果

### 4. 采样策略对比 (P.5)
| 策略 | 噪声比例 | 多样性 | 最终效果 |
|------|---------|--------|---------|
| Beam search | 19% | 低 | 差 |
| Nucleus sampling | 25% | 高 | **好** |

## 四、实验配置

### 1. 预训练数据集
- **基础版 (14M 图像)**: COCO + VG + CC + SBU
- **扩大版 (129M 图像)**: 14M + 1.15 亿网络新图片
- CapFilt 后文本数：从 15.3M → 24.7M

### 2. 评估任务与指标
| 任务 | 数据集 | 指标 |
|------|--------|------|
| 图文检索 | Flickr30K (1K test)、COCO (5K test) | R@1, R@5, R@10 |
| 图像描述 | COCO Caption (Karpathy test)、NoCaps val | B@4, C (CIDEr), S (SPICE) |
| 视觉问答 | VQA v2.0 (test-dev, test-std) | Accuracy |
| 自然语言推理 | NLVR2 (dev, test-P) | Accuracy |
| 视频检索 | MSRVTT | R@1, R@5, R@10, MdR |

### 3. 实验变体
| 变体 | 图像数 | 模型 | CapFilt |
|------|--------|------|---------|
| BLIP | 14M | ViT-B/16 | 无 |
| BLIP (129M) | 129M | ViT-B/16 | 无 |
| BLIP\_CapFilt\_L | 129M | ViT-B/16 | Nucleus 采样 |
| BLIP\_ViT\_L | 129M | ViT-L | 未明确 |

## 五、关键结论

1. MED 统一架构参数量比分离架构减少约 30%，且性能更好
2. CapFilt 显著提升数据质量，零样本检索 IR@1 从 82.1 → 84.9（Flickr30K）
3. Nucleus sampling 虽噪声更高，但多样性好，配合 Filter 后效果优于 Beam search
4. Captioner 和 Filter 必须独立微调以避免确认偏差
5. BLIP 在图文检索、图像描述、VQA、NLVR2 等多个任务上达到当时的 SOTA

## 六、与已有方法的区别

| 维度 | 已有方法 | BLIP |
|------|---------|------|
| 模型架构 | 编码器 或 编码器-解码器 | MED 统一架构，三种模式共享参数 |
| 预训练目标 | 单一目标（ITC 或 LM 等） | ITC + ITM + LM 三目标联合 |
| 数据处理 | 直接使用原始数据 | CapFilt 自举机制 |
| 灵活性 | 难以同时胜任理解与生成 | 支持理解（编码）与生成（解码） |
